### 2.1 Generación de ADR-009 (Primera parte de sesión con Claude)

**ADR-009 – Estructura y Organización del Proyecto** fue **generado en esta misma sesión 08** utilizando Claude (Anthropic) como copiloto LLM.

**Contexto de generación:**
- El usuario proporcionó al inicio de sesión los ADRs 001-005 (que ya existían de sesiones previas con Gemini y ChatGPT)
- Se solicitud a Claude generar ADR-009 para completar la documentación arquitectónica
- Claude creó ADR-009 con criterios de decisión para la estructura física del proyecto

**¿Qué aporta ADR-009?**
- Define la **estructura de carpetas y organización del proyecto** (backend/, frontend/, docker/, docs/, etc.)
- Establece **convenciones de código** y patrones de organización para Clean Architecture
- Proporciona **guías de modularización** alineadas con los Bounded Contexts definidos en ADR-003
- Documenta **políticas de naming**, ubicación de tests, y estructura de persistencia
- Facilita **onboarding** de nuevos desarrolladores con estructura clara y racional

**Decisiones clave de ADR-009:**
- Separación clara entre backend (Go) y frontend (Vue.js)
- Estructura modular por dominios (party/, producto/, tarificacion/, ventas/, mes/)
- Ubicación de tests junto al código (unit tests) y en `tests/integration/`
- Configuración centralizada en `config/`
- Documentación y diagramas en `docs/`

**Archivo:** `docs/adr/ADR-009-estructura-proyecto.md` ✅

## 4. Decisiones Arquitectónicas Consolidadas

### Stack Tecnológico (ADR-001)

- **Backend:** Go 1.21+, Gin Gonic, GORM (solo infraestructura)
- **BD:** PostgreSQL 15+
- **Frontend:** Vue.js 3, Composition API, Pinia, Tailwind CSS
- **Documentos:** Web-to-Print (HTML/CSS en frontend)
- **Despliegue:** Docker Compose
- **Seguridad:** JWT, roles básicos

### Arquitectura Aplicada (ADR-002, ADR-003)

- **Clean Architecture** con rigor asimétrico
- **DDD** en núcleo de dominio (Party, Producto, Tarificación)
- **Monolito modular** con Bounded Contexts explícitos
- **5 dominios principales:** Party, Producto, Tarificación, Ventas, MES
- **Extracción futura** preparada desde diseño

### Ciclo de Vida (ADR-004)

**3 Fases + Frontend paralelo:**

1. **Fase 0 (1-2 semanas):** Fundaciones técnicas
   - Infraestructura, Docker, PostgreSQL
   - Autenticación JWT, roles básicos
   - Pipeline de tests TDD

2. **Fase 1 (4-6 semanas):** Dominio base
   - Party + Producto + Tarificación (núcleo económico)
   - Auditoría mínima
   - Frontend: CRUD completo

3. **Fase 2 (3-4 semanas):** Pedidos estándar
   - Gestión completa de pedidos
   - Cálculo automático de precios
   - Generación de documentos (Web-to-Print)

4. **Fase 3 (3-4 semanas):** MES
   - Producción personalizada
   - Terminal de taller
   - Gestión documental (NAS)

**Total estimado:** 11-16 semanas

### Modelo de Dominio (ADR-005)

**Party como concepto fundacional:**
- Un Party, múltiples roles (Cliente, Proveedor, ambos)
- Jerarquías solo para clientes
- Herencia de descuentos en jerarquías
- Proveedores como fuente de costes (MVP sin compras formales)

**Tarificación como núcleo económico:**
```
Precio final = ((Coste base + Modificadores variante) × (1 + Margen)) × (1 - Descuento total)
```
