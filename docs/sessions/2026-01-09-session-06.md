## 4. Notas de trabajo
- Se valida que el **orden de implementación** (Party → Producto → Tarificación → Pedidos → MES) es coherente con el flujo económico real del negocio.  
- Se refuerza que el **motor de tarificación** es núcleo de dominio y debe construirse únicamente sobre Party y Producto, sin dependencias prematuras.  
- Se acuerda explícitamente que el **frontend se desarrolla en paralelo en todas las fases**, pero sin condicionar el orden del backend.  
- Se clarifica la separación estricta entre **MVP y Post-MVP**, evitando contaminación de alcance.  
- Se ajusta la documentación para reflejar que los **proveedores en MVP existen exclusivamente como fuente de costes**, no como módulo de compras.
