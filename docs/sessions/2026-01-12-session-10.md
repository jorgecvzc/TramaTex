## 🧪 ESPECIFICACIONES DETALLADAS

### Pinia Store (authStore.ts)

```typescript
// Estado inicial
const state = () => ({
  token: null,
  user: null,
  isAuthenticated: false,
  loading: false,
  error: null
})

// Mutaciones
- setToken(token: string)         // localStorage sync
- setUser(user: User)
- setLoading(bool)
- setError(error: string | null)
- clearAuth()                     // logout

// Getters
- isAuthenticated: boolean
- hasToken: boolean
- currentUser: User | null
```

```typescript
// Métodos
- login(email: string, password: string): Promise<User>
- logout(): void
- refreshToken(): Promise<string>  // Silent refresh
- loadFromStorage(): void          // On app init
- isAuthenticated(): Ref<boolean>  // Computed
```

    <input v-model="password" type="password" required>
    <button type="submit" :disabled="loading">
      {{ loading ? 'Autenticando...' : 'Ingresar' }}
    </button>
    <p v-if="error" class="error">{{ error }}</p>
  </form>
</template>

// Methods
- handleSubmit(): login → redirect

## 📚 DECISIONES ARQUITECTÓNICAS A TOMAR

### Decisión 1: Pinia vs Vuex
**Contexto:** Necesitamos state management para auth.

**Alternativas:**
- Opción A: Vuex (older, más boilerplate)
- Opción B: Pinia (nuevo, recomendado, simpler) - ELEGIDA

**Justificación:** Pinia es official Vue 3 successor de Vuex, menos boilerplate, mejor DX.

### Decisión 2: localStorage vs sessionStorage
**Contexto:** Persistir token entre page reloads.

**Alternativas:**
- Opción A: localStorage (persiste entre sessions)
- Opción B: sessionStorage (limpia al cerrar tab)
- Opción C: Memory only (se pierde en refresh)

**Decisión adoptada:** Opción A (localStorage)

**Justificación:** UX mejor (remember user), similar a apps modernos.

### Decisión 3: Token en localStorage vs Cookie
**Contexto:** Storage para JWT token.

**Alternativas:**
- Opción A: localStorage + axios header (vulnerable a XSS)
- Opción B: HttpOnly cookie (más seguro CSRF)

**Decisión adoptada:** Opción A (localStorage)

**Justificación:** Simpler para implementación rápida, XSS risk mitigado con CSP, CSRF con token en header.
