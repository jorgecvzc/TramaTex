## 4. Notas de trabajo
- Se confirma que **tarificación depende de Party y Producto**, incluyendo clientes, proveedores, variantes de productos y jerarquías empresariales.  
- Party se modela como entidad única con roles de cliente y proveedor, soportando jerarquía matriz/dependientes.  
- Productos incluyen variantes (talla, color, arreglos) y categorías para estructurar el catálogo. Variantes influyen en precio, categorías solo en organización.  
- Proveedores pueden tener reglas globales o por tipo de producto; históricos de costes integrados a tarificación.  
- La infraestructura se introduce **solo cuando existe un caso de uso validado**; persistencia inicial permitida para Party y Producto.  
- TDD obligatorio para dominio y casos de uso; mocks solo en fronteras de aplicación.  
- Se prioriza la ejecución incremental por módulos respetando dependencias reales para minimizar riesgos funcionales y estructurales.
