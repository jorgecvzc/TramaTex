5. Configuración inicial de pipelines de tests TDD y cobertura de dominio crítico.

---

## 4. Notas de trabajo
- Party / Organización y Producto / Variante / Categoría son dominios fundacionales para Tarificación.  
- Tarificación no se desarrolla aislada: depende de Party y Producto.  
- Infraestructura introducida solo cuando un caso de uso está validado.  
- Frontend se implementa en paralelo en todas las fases para garantizar operatividad progresiva.  
- Se mantiene disciplina estricta para proteger la integridad del dominio frente a decisiones técnicas tempranas.  
- Considerar delegación de generación de documentos al frontend (Web-to-Print) para reducir carga del servidor.

## 5. Decisiones y ADR
- Nueva decisión arquitectónica: [[ADR-006 – Orden de Implementación de Módulos y Creación de Infraestructura]]  
- Justificación: Establece un orden incremental de desarrollo de módulos core y la introducción controlada de infraestructura, garantizando que el frontend sea funcional al final de cada fase y que los módulos críticos del dominio se implementen con TDD y trazabilidad total.
